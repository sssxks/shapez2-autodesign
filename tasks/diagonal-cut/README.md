# 对角提取 / Diagonal cut

两份横向 1×2、三层蓝图：1 口 12 带输入，2 口各 12 带输出。左半平台上方输入，左半平台下方、右半平台下方输出，与用户提供的接口布局一致。

- NE–SW：`CuCuCuCu` → 两路 `Cu--Cu--`。
- NW–SE：`CuCuCuCu` → 两路 `--Cu--Cu`。

用途是四个象限相同的常规形状。每条输入分给四个并联单元，每个单元整切、旋转两半、换半，再旋转其中一路，保留全部材料。输入和两个输出的内部带序有置换。每份 993 个建筑，包括 48 个整切机、48 个换半机，三层完全相同。

运行 `cargo run --release -p diagonal-cut` 生成两份 `.spz2bp`，并在隔离的原生 1.2.0-rc3 宿主中验收。检查原生导入与占地、12 个输入、24 个输出、120 秒预热后的 120 秒持续满载输出和全部输出形状。只有通过后才发布 `%TEMP%/shapez-lab/tasks/diagonal-cut/latest.json`。`*-harness.spz2bp` 为带外部星际传送带的测试夹具，导入工厂使用不带 harness 后缀的文件。

已通过运行：`1794053519987-14548-0`；验收报告：`1794053520010-14548-1/report.json`。本次交付选择 1×2，没有产出 1×1 版本。

合并总线使用仅开放所需方向的双输入合并器，首项使用转弯带；原生连接图中的所有平台内连接口均已连接，只有测试夹具的三个外部星际接口开放。图库图标参照现有绿色形状与 ArrowDown 样式，上排完整绿色圆形和箭头，下排两个相同的绿色对角。两个图标通过原生导入/导出和版本 5 图库校验。


## 通用溢流蓝图朝向修正

`cargo run --release -p diagonal-cut -- overflow <原蓝图路径>` 保持原来的 1×2 三层布局、三个接口和溢流垃圾路径。每条输入先经过两台并联的 90° 旋转器，再进入原切割单元；总共 24 台输入旋转器。ABAB 先变为 BABA，经原切割结构后，左下出口得到 A-A-，右下出口得到 -B-B。生成器从仓库中的 `templates/overflow-reference.spz2bp` 读取各层原始溢流布线，命令参数仅确定图库发布目录。各层只重建输入旋转区，保留第二、第三层的下降升降带；垃圾桶只在底层。成品共 1072 个建筑。

原生验收使用每带 2 件/秒的受限供料，逐出口校验形状与 99% 满速阈值，包含正常输出、左侧全堵、右侧全堵、恢复四个阶段，各预热 120 秒并测量 120 秒。通过报告 `1794121539492-20120-1/report.json`：正常与恢复时 24 条带各 240 件；单侧堵塞时另一侧 12 条带仍各 240 件，堵塞侧为零。原生导入和版本 5 图库校验通过。仅验收成功后发布至原图库中的“溢流·朝向修正”文件。

旧实现把旋转器放在汇流后的满带上，只有半速，其 49% 阈值不能作为满速验收；此实现已取代旧方案。

放置回归：旧版复制底层到上层，误把下降升降带替换为上层垃圾桶，触发原生 OnlyOnGroundLayerRequirement，导致玩家放置时整批建筑被拒。共享加载器现检查建筑组的 PlacementRequirements；无枢纽的隔离世界仅排除两种专属枢纽规则。2026-11-08 已在用户当前游戏中实际放置，确认建筑出现，日志无新增放置失败，并撤销测试平台。
