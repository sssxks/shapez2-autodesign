# 脚手架竖列配方任务

本目录拥有单层及脚手架竖列构造策略、可接受输入范围和用例枚举。公共 `shapez-model` 提供加工 DAG 和验证后端口模型，原生宿主提供设备运算执行。

## 配方编译器原型

`cargo run -p scaffold-recipe -- plan 'WwcbWwcb:P-cwP-cw:WgP---P-'` 使用 Rust 生成加工 DAG，再由独立游戏实例逐节点执行原生形状运算。输出位于本次运行目录：`recipe.json`、`recipe-verification.json`、`verified-recipe.json` 和 `recipe.txt`。节点记录设备操作、上游节点、期望形状和原生输出端口。真实原料只允许四种未染色完整基础形状与完整销钉；颜色限定 RGB 可混合的七色。没有把目标或中间形状作为原料注入。

这是自动配方/加工网表原型，尚未生成摆放在地图上的自动控制工厂。它验证形状变换，不测机器吞吐；DAG 的共享节点需要在布局阶段配置分流和设备数量。流体颜色参数假定上游已有相应 RGB 混色供应。

单层策略：普通象限直接染色、切割、旋转；晶体象限通过三象限圆形掩模结晶，再切出孤立晶体。先以旋转后的交换构成两个半边，再交换合成整层。最终晶体接缝产生在最后一次切割之后。空位通过不连接对应分支实现，不需要“空形状”原料。当前输入字母表内的任意非空单层都有该构造。

多层策略：各竖列独立制造，用其他三个象限的圆形作临时隔离和支撑。按层堆叠普通材料，晶体位置先放销钉，然后原地结晶。完成后一次性切出整根竖列，最后交换合并四列。这避免把晶体当作上层材料堆叠造成掉落破碎。

当前多层适用范围：至多四层，每列自底向上无内部空洞，且保留的销钉上方没有之后还要结晶的位置。不符合此条件会拒绝这条构造策略，含义是“需要其他配方策略”，不代表形状不可制造。里程碑 `WwcbWwcb:P-cwP-cw:WgP---P-` 的 61 节点配方已逐节点通过原生运算。直接按层堆叠的旧候选在第二层丢失晶体，已由竖列策略取代。

`cargo run -p scaffold-recipe -- check` 生成 624 个非空单层结构用例，符号集为空、销钉、圆形、白晶、红晶；`cargo run -p scaffold-recipe -- test` 在同一宿主内验证。该集合覆盖不同空位/销钉/普通材料/晶体的四象限组合以及异色晶体接合；不是全部颜色与普通形状的穷举。

### 一般可制造性判定

固定游戏版本、最大层数、原料集合和实际可用设备后，规范化形状的集合有限。以原料为初始集合，对所有可用的一元/二元加工运算反复求闭包；每当出现新形状，记录产生它的操作与父节点。如果得到目标，回溯就是制造配方；如果达到不动点仍无目标，才可判定在这些输入条件下不可制造。该算法是完整判定算法，但全状态空间和二元组合极大。

实现上优先使用已知构造（单层、带脚手架的竖列），再扩展有预算的配方搜索。返回状态应区分：找到并原生验证的配方、完整闭包排除、当前策略/搜索预算未解决。当前原型只实现构造与原生验证，没有实现全状态闭包，也不输出“不可制造”。没有一种简单的“看起来有支撑就能制造”检查可以替代完整加工路径。

单层构造把单层可制造性问题消去了，但多层仍有晶体掉落、切断连接组、销钉被后续结晶替换、跨层支撑和截层等约束。搜索可将单层构造作为宏操作，不必重复搜索它的每个切割步骤。


## 独立入口与产物

```powershell
cargo run -p scaffold-recipe -- plan 'WwcbWwcb:P-cwP-cw:WgP---P-'
cargo run -p scaffold-recipe -- check
```

每次运行有独立目录。成功规划及原生验证后发布 `tasks/scaffold-recipe/latest.json`；用例集生成后发布 `tasks/scaffold-recipe-check/latest.json`。原始逻辑 DAG 用 `NodeId` 引用共享形状；`VerifiedRecipe` 将每条连接解析为明确的 `OutputRef { node, port }`，供后续实体布局使用。
